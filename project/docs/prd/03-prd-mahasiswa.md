# PRD Role: Mahasiswa Magang

## Ringkasan
Mahasiswa menggunakan sistem untuk pendaftaran, presensi, logbook harian, laporan akhir, dan melihat penilaian.

## Tujuan Produk (Mahasiswa)

1. Menyederhanakan proses pendaftaran magang.
2. Memudahkan pengisian presensi dan logbook harian.
3. Memberikan visibilitas status validasi dan nilai akhir.

## Fitur Utama

1. Registrasi (mandiri/admin-generated)
2. Login/logout mahasiswa
3. Kelola profil magang
4. Upload berkas persyaratan
5. Submit pendaftaran
6. Cek status pendaftaran
7. Presensi check-in/check-out (selfie)
8. Input logbook + upload bukti
9. Revisi logbook ditolak mentor
10. Upload laporan akhir
11. Lihat nilai akhir
12. Akses sertifikat (opsional)

## Daftar Kebutuhan Fungsional

1. Mahasiswa dapat registrasi dan login.
2. Mahasiswa dapat melengkapi profil dan periode.
3. Mahasiswa dapat upload berkas dalam format yang ditentukan.
4. Mahasiswa dapat melihat status pendaftaran real-time.
5. Mahasiswa dapat check-in/check-out satu kali per hari kerja.
6. Mahasiswa dapat input logbook harian dan lampiran.
7. Mahasiswa dapat memperbaiki logbook jika ditolak mentor.
8. Mahasiswa dapat upload laporan akhir sebelum deadline.
9. Mahasiswa dapat melihat nilai akhir ketika sudah dipublikasi.

## Kriteria Penerimaan (Acceptance Criteria)

1. Status pendaftaran tampil jelas: pending/diterima/ditolak/selesai.
2. Presensi tersimpan dengan timestamp dan foto selfie.
3. Logbook tidak dapat dikirim tanpa deskripsi kegiatan.
4. Laporan akhir hanya menerima format file yang didukung.
5. Nilai akhir tampil setelah finalisasi mentor/admin.

## Data yang Dibutuhkan

1. Data akun mahasiswa
2. Data profil magang
3. Data berkas pendaftaran
4. Data presensi
5. Data logbook
6. Data laporan akhir
7. Data penilaian
8. Data sertifikat

## KPI Mahasiswa

1. Tingkat kelengkapan profil
2. Tingkat kepatuhan presensi harian
3. Tingkat ketepatan input logbook
4. Tingkat kelulusan magang
